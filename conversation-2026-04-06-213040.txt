❯ 그렇군, expo 앱에서 실행하면 안되는 이유는 뭘까?                              

⏺ Expo Go(네이티브 앱)에서는 expo-secure-store가 정상 동작해서 그 에러는 안 떠.
  만약 Expo Go에서도 안 된다면 다른 원인일 가능성이 커.

  네이티브에서 안 되는 흔한 이유들:

  1. SDK/패키지 버전 불일치 — expo-secure-store가 현재 Expo SDK 버전과 안 맞으면
   네이티브 모듈 링크가 깨져서 똑같이 undefined 나올 수 있어. (npx expo install 
  expo-secure-store로 맞춰야 함)
  2. 개발 빌드 vs Expo Go — 커스텀 네이티브 코드가 들어간 경우 Expo Go로는 못
  열고 dev client 빌드가 필요해.
  3. 메트로 캐시 문제 — npx expo start -c로 캐시 날리면 해결되는 경우 있음.
  4. API 호출 자체 에러 — 스택트레이스가 services/api.ts:104 response.ok 체크
  부분이라, SecureStore 에러랑 별개로 백엔드 응답이 실패하는 것일 수도 있어.
  (토큰 못 읽음 → 인증 실패 → 401 → throw)

  웹에서 본 에러는 SecureStore 미지원이 1차 원인이고, 그게 토큰 조회를 막아서
  API 호출이 연쇄적으로 터진 거로 보여. 네이티브에서 멀쩡하면 진짜 웹 전용
  이슈인거고, 네이티브도 같이 터지면 버전/캐시 쪽 의심해봐! 🐱

  - orders = 묶음(헤더), transactions/payments = 라인아이템(자식)
  - 부분환불은 "라인 단위 상태 변경"으로 표현됨:

    - 각 라인에 refunded_amount 누적

  refunded)

  필요한 추가 설계 (지금 미리 잡아두면 좋은 것):

  1. refunds 테이블 (나중에 만들더라도 자리는 남겨두기)

  created_at

  2. orders.status enum 확장
    - pending → paid → partially_refunded → refunded → cancelled
  3. 금액 무결성 규칙
    - sum(refunds.amount where order_id=X) ≤ orders.total_amount
    - DB 트리거 or 애플리케이션 레벨 체크 (세이가 잡을 부분)

  - PayPal/DANA/SmileyPay: PG사 API가 부분환불 지원 여부 확인 필요
